# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

MachineCard의 이미지 로딩 속도를 개선하기 위한 사전 조사다.
목표: 카드가 표시하는 실제 크기에 맞는 축소 이미지(Supabase Image Transformation)를
받아오도록 이미지 URL 조립 로직만 바꾸는 것. 레이아웃(요소 크기/위치/스타일)은 절대
건드리지 않을 것이므로, 그 경계를 명확히 하기 위해 먼저 정확한 코드를 확인한다.

## 조사 항목

### 1. src/components/MachineCard.tsx 전체 구조 확인

- 파일 전체를 확인하고, 다음을 정확한 줄 번호와 함께 보고:
  a. 컴포넌트가 받는 props 시그니처 전체 (특히 `machine`, `variant`, `width` 등
     이미지 크기와 관련된 props가 정확히 어떤 이름과 타입인지)
  b. 이미지 소스를 결정하는 코드 (현재 알려진 위치: 69번째 줄 근처
     `const resolvedImageUrl = machine.imageUrl ?? ...` 부분) — 이 줄의 정확한 현재 코드와
     앞뒤 문맥 10줄씩
  c. 실제 이미지를 렌더링하는 JSX 부분 (현재 알려진 위치: 93~98줄 근처) — 어떤 컴포넌트를
     쓰는지 정확히 확인 (`Image` from 'react-native'인지, `expo-image`의 `Image`인지,
     import 구문 기준으로 확인)
  d. `variant="grid"` 와 `variant="detail"` 각각에서 카드의 실제 픽셀 너비가 어떻게
     결정되는지 (props로 직접 받는지, 내부에서 `Dimensions`로 계산하는지, 고정값인지)
  e. PixelRatio를 이미 사용하고 있는지 (`import { PixelRatio }` 여부와 사용 위치)

### 2. getMachineImageUrl 사용 현황 재확인

- `src/lib/machineImageUrl.ts`의 `getMachineImageUrl` 함수 시그니처 재확인 (이미 알고
  있는 내용이지만 변경 여부 확인 차 다시 한 번 grep)
- `MachineCard.tsx` 내부에서 이 함수를 이미 import/사용하고 있는지, 아니면 전혀
  사용하지 않고 위 1-b의 fallback 로직만 쓰고 있는지 확인

### 3. MachineCard를 호출하는 곳에서 width를 넘기지 않는 케이스 확인

다음 파일들에서 `<MachineCard .../>` 호출부를 찾아서, `width` prop을 명시적으로
넘기는지 여부를 각각 표로 정리:
- src/screens/FavoritesScreen.tsx
- src/screens/flow/PostWorkoutLogModal.tsx (여러 곳일 수 있음, 전부)
- src/screens/manager/ManagerDashboard.tsx (여러 곳일 수 있음, 전부)
- src/screens/flow/MachineDetailModal.tsx
- src/screens/admin/AdminDashboard.tsx (AdminMachineItem 내부 호출부 포함)

각 호출부마다:
- 파일 경로 + 줄 번호
- `width` prop 전달 여부와 전달한다면 어떤 값(변수명)인지
- `variant` 값 (grid/detail)

### 4. src/screens/olympic/OlympicTradingCard.tsx 확인

- MachineCard와 별개로 자체적으로 이미지 URL을 조립하는 부분(앞서 확인된
  `machine.imageUrl ?? \`${SUPABASE_STORAGE_URL}/${machine.id}.webp\`` 근처)의 정확한
  현재 코드와, 이 컴포넌트가 렌더링되는 카드의 실제 픽셀 크기를 알 수 있는 근거
  (width prop, 고정 크기 스타일 등)를 확인

## 출력 형식

각 항목에 대해 파일 경로 + 정확한 줄 번호 + 코드 그대로. 3번 항목은 표로 정리.

## 중단 조건

- `MachineCard.tsx`가 `width` prop을 아예 받지 않는 구조라면 (즉 내부에서 크기를
  자체 계산), 그 계산 로직 전체를 그대로 보고하고 중단 — 이 경우 수정 방식이
  달라져야 하므로 구현 태스크로 넘어가지 않고 먼저 보고
