where the targetMuscle or brand field values do not exactly match the filter chip values.

  - brand field that is a non-empty string
  - name field that is a non-empty string
  - category field that is a non-empty string
  - id field that is a unique non-empty string
Step 4: If any machine is missing these fields or has mismatched casing, fix them.
Step 5: Also check that fetchGymsWithMachines returns gym objects where each gym has a machines array

    gyms.filter(gym => gym.machines.some(m => mIds.has(m.id)))

BUG FIX 2: Journal not showing saved workout data
==================================================

PROBLEM:
When a user logs a workout in PostWorkoutLogModal, the data is saved somewhere.
But JournalScreen reads data using:
  const { data: fetchedSessions, loading, refetch } = useFetch(() => fetchWorkoutLogs(userId), [userId])
The saved workout is not appearing in JournalScreen after saving.
This means either:
  A) PostWorkoutLogModal saves to a different store than fetchWorkoutLogs reads from, OR
  B) refetch() is not being called after the modal closes, OR
  C) Both

HOW TO FIX:
Step 1: Open src/screens/flow/PostWorkoutLogModal.tsx and find where the workout is saved on completion.
  Look for where onClose is called after saving, or where the workout data is written.
Step 2: Open src/lib/db.ts and find the fetchWorkoutLogs function.
  Find what in-memory store or array it reads from.
Step 3: Find where PostWorkoutLogModal writes the saved workout.
  If it writes to a different store (e.g. workoutSessions.ts or a local array), 
  change it to write to the same store that fetchWorkoutLogs reads from.
Step 4: Make sure the saved WorkoutLog object matches the WorkoutLog type in src/data/types.ts exactly.
  Check all required fields: id, userId, gymId, gymName, date, machines array, etc.
Step 5: In JournalScreen.tsx, find where the PostWorkoutLogModal onClose callback is handled.
  After the modal closes with a saved workout (onClose(true) or similar), call refetch().
  Example:
    onClose={(saved) => {
      setLogVisible(false)
      if (saved) refetch()
    }}
Step 6: Also find any other places in JournalScreen where PostWorkoutLogModal is rendered and apply the same fix.
Step 7: Test the data flow by tracing: save in modal → stored in correct place → fetchWorkoutLogs reads it → JournalScreen shows it.
