# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

HomeScreen의 "오늘의 오운완" 섹션에 "24시간 이내 게시물이 너무 적으면 기간을
넓혀서 다시 조회"하는 폴백 로직을 추가하기 위한 사전 조사다. 코드는 수정하지 않는다.

## 조사 항목

### 1. fetchActiveFeedPosts / getActiveFeedPostsCached 정확한 구조

- `src/lib/db/feedPosts.ts`에서 `fetchActiveFeedPosts()` 함수 전체 코드 (이전 조사에서
  25~38번째 줄로 확인된 부분, 정확한 현재 코드로 재확인)
- `getActiveFeedPostsCached()`가 정의된 위치(파일이 다를 수 있음, grep으로 찾을 것)와
  전체 코드 — 캐시 TTL(60초로 언급됨), 캐시 저장 방식(모듈 스코프 변수인지, 다른
  방식인지), `invalidateActiveFeedPostsCache()`와의 관계
- `fetchActiveFeedPosts()`가 다른 곳(WorkoutFeedScreen.tsx 등)에서도 호출되는지
  전부 grep으로 확인 (이 함수 자체를 변경하면 영향받는 범위 파악 목적)

### 2. HomeScreen.tsx의 오운완 로딩 흐름 전체

- `useFocusEffect` 안에서 `getActiveFeedPostsCached()`를 호출하는 부분(이전 조사에서
  399~412번째 줄로 확인된 부분)의 앞뒤 문맥을 넓게(최소 30줄 전후) 다시 확인
- `hasFeedMuscleFilter`, `feedMuscleFilter` 등 관련 변수들이 어디서 어떻게 계산되는지
- `setOunwanPosts`가 최종적으로 호출되는 모든 지점

### 3. WorkoutFeedPost의 createdAt 필드 활용 가능성

- `WorkoutFeedPost.createdAt`이 ISO 8601 문자열이라고 확인된 바 있음 — 이 필드를
  클라이언트에서 필터링/정렬에 이미 사용하는 코드가 있는지 (있다면 폴백 시 "24시간
  이내인지" 클라이언트에서 재확인할 때 참고 가능)

### 4. 유사한 폴백 패턴이 이미 코드에 있는지 확인

- 조사에서 언급된 "부위 매칭 결과가 0개면 필터 해제 후 전체로 폴백"하는 기존 패턴의
  정확한 코드(HomeScreen.tsx, 이전 조사에서 399~407번째 줄 근처)를 다시 한 번 정확히
  확인 — 이 패턴과 동일한 스타일로 시간 범위 폴백을 구현할 수 있는지 판단하기 위함

## 출력 형식

각 항목에 대해 파일 경로 + 정확한 줄 번호 + 코드 그대로.
