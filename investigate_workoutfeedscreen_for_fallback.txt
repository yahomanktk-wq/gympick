# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

`src/screens/WorkoutFeedScreen.tsx`에 HomeScreen과 동일한 "24시간 이내 3개 미만이면
기간 제한 없이 폴백 조회" 로직을 적용하기 위한 사전 조사다. 코드는 수정하지 않는다.

## 조사 항목

### 1. 게시물 로딩 흐름 전체

- 비로그인 분기 (이전 조사에서 488~493번째 줄 근처로 확인된 부분)와 로그인 분기
  전체 코드를 정확한 줄 번호와 함께 확인 (최소 480~560번째 줄 범위, 필요하면 더
  넓게)
- 로그인 시 "내 게시물 + 서버 전체(24h) 게시물을 합쳐 중복 제거 후 sortByLatest()"
  라고 조사된 부분의 정확한 코드 (내 게시물은 어디서 오는지 — 로컬 세션 변환인지
  별도 쿼리인지도 확인)
- `getActiveFeedPostsCached()`를 호출하는 정확한 위치 전부 (grep, 정확한 줄 번호)
- 이 화면에 있는 탭 필터(전체 / 내 헬스장 / 주변 5km)와 부위 칩 필터가 게시물
  배열의 어느 단계에 적용되는지 (fetch 직후인지, 렌더 직전인지)
- `posts`(또는 유사 이름의 state)가 최종적으로 화면에 몇 개까지 노출되는지 관련
  slice/limit 코드 전부

### 2. 카운트다운 배지 정확한 구조

- "N시간 후 사라져요" 배지(153~164번째 줄 근처로 확인된 부분)가 어느 컴포넌트에
  속해 있는지 (`FeedGridCard`인지 다른 이름인지), 그 컴포넌트의 props 전체와
  이 배지 부분의 전체 JSX 문맥(앞뒤 15줄)
- 이 배지가 `post.createdAt` 외에 다른 값도 참조하는지

### 3. HomeScreen에서 이미 구현된 폴백 로직 재확인 (참고용)

- `src/screens/HomeScreen.tsx`의 현재(수정 완료된) 폴백 관련 코드 전체를 다시 한 번
  정확히 확인한다 — `let posts`, `posts.length < 3` 조건, `fetchActiveFeedPosts(null)`
  호출, `ounwanIsFallback` state까지 전부 포함해서 그대로 인용

### 4. WorkoutFeedScreen 헤더/타이틀 텍스트 확인

- 화면 상단 타이틀("오늘의 오운완"으로 확인된 587번째 줄 근처)과, 탭별 빈 상태
  문구(98~100번째 줄 근처 "최근 방문한 헬스장의 오운완이 없어요" 등)의 정확한
  현재 코드 전체 확인 — 폴백 적용 시 이 문구들도 HomeScreen처럼 손봐야 할지
  판단하기 위함

## 출력 형식

각 항목에 대해 파일 경로 + 정확한 줄 번호 + 코드 그대로.
마지막에 "WorkoutFeedScreen의 현재 게시물 로딩~렌더링 흐름"을 간단한 순서로 요약.
