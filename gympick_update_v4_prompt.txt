BUG FIX 2: Favorites state not synced between FavoritesScreen and MachineDetailModal
==================================================

PROBLEM:
A machine added to favorites in FavoritesScreen shows as favorited there,
but when opening MachineDetailModal for that same machine, it shows as NOT favorited.
This means favorites state is stored in local component state (useState) in FavoritesScreen
and not shared with MachineDetailModal.

HOW TO FIX:

Step 1: Open src/data/machineReviews.ts (or wherever getUserFavorites and favorite functions are defined).
  Check if there is a global in-memory favorites array.
  If yes, make sure both FavoritesScreen and MachineDetailModal read from and write to this same array.

Step 2: Open src/screens/FavoritesScreen.tsx
  Find the removeMachine function and the favorites state.
  Make sure removing a favorite calls the global store function (e.g. removeUserFavorite or similar).
  Not just a local setState.

Step 3: Open src/screens/flow/MachineDetailModal.tsx (or wherever the machine detail is shown)
  Find where it checks if the machine is favorited.
  Make sure it reads from the same global store (e.g. getUserFavorites('u1').includes(machine.id)).
  Make sure the toggle favorite button writes to the same global store.

Step 4: Both screens must use the same source of truth for favorites.
  If no global store exists, create one in src/data/favoritesStore.ts:

    const favoriteMachineIds: string[] = []

    export function getFavoriteMachineIds(): string[] {
      return [...favoriteMachineIds]
    }

    export function addFavoriteMachine(id: string): void {
      if (!favoriteMachineIds.includes(id)) favoriteMachineIds.push(id)
    }

    export function removeFavoriteMachine(id: string): void {
      const idx = favoriteMachineIds.indexOf(id)
      if (idx !== -1) favoriteMachineIds.splice(idx, 1)
    }

    export function isFavoriteMachine(id: string): boolean {
      return favoriteMachineIds.includes(id)
    }

  Then update both FavoritesScreen and MachineDetailModal to use this store.

CHANGE 2: Workout logging flow - routine selection redesign
==================================================

Read PostWorkoutLogModal.tsx carefully before making changes.
The current flow has a step called something like "머신을 추가해보세요" or machine selection step.

The routine selection screen shows 4 options:
  1. 새 루틴 작성하기
  2. 이전 운동일지 참고하기
  3. 헬스장 추천 루틴
  4. 다른 유저 루틴

--- FIX FOR "새 루틴 작성하기" ---

CURRENT BEHAVIOR (wrong):
  User taps 새 루틴 작성하기
  → Goes to "머신을 추가해보세요" step with empty machine list
  → User manually adds machines one by one

NEW BEHAVIOR (correct):
  User taps 새 루틴 작성하기
  → Skip the empty "머신을 추가해보세요" step entirely
  → Go DIRECTLY to machine selection screen
  → Show all machines in the selected gym that match the selected body part
  → Each machine displayed as sports card (SelectableMachineCard if it exists, or MachineCard)
  → User taps ONE machine card to select it
  → Tap "이 머신으로 운동 시작" button
  → Go to set logging for that machine
  → After saving sets, return to machine selection screen
  → Previously logged machines show a "완료" checkmark badge
  → Repeat until user taps "운동 종료"

Implementation:
  In the flow after tapping 새 루틴 작성하기,
  set the machine list state to all machines matching gym + body part immediately,
  then navigate to the machine selection screen (skipping the empty add-machines step).

--- FIX FOR 이전 운동일지 참고하기 / 헬스장 추천 루틴 / 다른 유저 루틴 ---

CURRENT BEHAVIOR (wrong):
  User selects a routine reference
  → Goes to "머신을 추가해보세요" step with empty machine list
  → Machines from the routine are NOT pre-loaded

NEW BEHAVIOR (correct):
  User selects a routine reference (past log, gym routine, or user routine)
  → Goes to "머신을 추가해보세요" step
  → The machine list is PRE-POPULATED with machines from the selected routine
  → The machines are already shown in the list, user cannot add or remove them
  → User taps "운동 시작" to begin
  → Set logging proceeds one machine at a time (same as 새 루틴 작성하기 flow)

Implementation:
  When user selects a past log / gym routine / user routine,
  extract the machine list from that selection,
  set it as the pre-populated machine list state,
  then navigate to the machine list screen with those machines already loaded.
  Hide the "머신 추가" button on this screen for these three paths.
  Show only the pre-loaded machines, no add/remove controls.
