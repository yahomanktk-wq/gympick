# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

`src/screens/WorkoutFeedScreen.tsx`(HomeScreen "오늘의 오운완" 더보기 버튼의 이동
대상 화면)에 HomeScreen과 동일한 폴백 로직(24시간 이내 게시물이 3개 미만이면
기간 제한 없이 재조회)을 적용하기 위한 사전 조사다. 코드는 수정하지 않는다.

## 조사 항목

### 1. 화면 전체 구조와 탭 구성

- 이 화면의 최상위 컴포넌트 이름과 시작/끝 줄 번호
- "전체 / 내 헬스장 / 주변 5km" 탭(이전 조사에서 언급됨)이 실제로 존재하는지,
  탭별 상태 변수명과 필터링 로직 전체
- 화면 타이틀 "오늘의 오운완"(587번째 줄 근처로 확인된 바 있음)이 정확히 어느
  탭/섹션에 해당하는지, 아니면 화면 전체의 고정 타이틀인지

### 2. 데이터 로딩 흐름 전체

- 비로그인 분기 (488~493번째 줄 근처, `getActiveFeedPostsCached().catch(...).slice(0, 4)`)
  전체 코드와 그 앞뒤 문맥
- 로그인 분기 (520번째 줄 근처) 전체 코드 — "내 게시물 + 서버 전체(24h) 게시물을
  합쳐 중복 제거 후 sortByLatest()"라고 조사된 부분의 정확한 현재 코드
- 이 로딩 함수가 `useFocusEffect`/`useEffect` 중 어디서 호출되는지, HomeScreen의
  `load()` 함수와 구조적으로 얼마나 비슷한지(그대로 같은 패턴을 적용할 수 있는지)

### 3. "N시간 후 사라져요" 카운트다운 배지 재확인

- 154~164번째 줄 근처 카운트다운 로직의 정확한 현재 코드
- 이 배지가 `FeedGridCard`(그리드 카드) 안에 있는지, 상세 모달에도 별도로 있는지
  (이전 조사에서 `detailPost` 상태로 상세 모달을 여는 코드가 있다고 언급됨 —
  623~640번째 줄 근처 `onPress={() => setDetailPost(item)}` 부분과 그 상세 모달
  렌더링 부분도 확인해서, 카운트다운 배지가 그리드 카드/상세 모달 양쪽에 다 있는지
  확인)
- 폴백을 적용하면 24시간이 훨씬 지난 게시물도 이 화면에 나타나게 되므로, 이 배지가
  그런 게시물에 대해 정확히 어떤 문구를 보여주게 되는지 (diffH가 매우 큰 경우
  `'곧 사라져요'`로만 표시된다고 이전 조사에서 확인됨 — 그대로 유지되는지 재확인)

### 4. 빈 상태 문구 확인

- "최근 방문한 헬스장의 오운완이 없어요" / "주변 5km 내 오운완이 없어요" / "오늘
  등록된 오운완이 없어요" (98~100번째 줄 근처로 확인된 바 있음) 각각이 어느 탭에
  대응하는지, 정확한 조건문과 함께 확인

### 5. HomeScreen과의 구조 비교

- HomeScreen의 폴백 구현에 쓰인 `fetchActiveFeedPosts(null)` 직접 호출 방식을 이
  화면에도 그대로 적용할 수 있는 구조인지, 아니면 탭이 여러 개라 "어느 탭에 폴백을
  적용할지"를 먼저 정해야 하는 구조인지 판단해서 보고

## 출력 형식

각 항목에 대해 파일 경로 + 정확한 줄 번호 + 코드 그대로.
마지막에 "이 화면에 폴백을 적용하려면 어떤 부분을 어떻게 바꿔야 하는지"에 대한
간단한 설계 방향 메모 (실제 수정은 하지 않음, 판단을 위한 참고용 의견만).
