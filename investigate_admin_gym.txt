■ 배경/방향
어드민 '헬스장 직접 등록' 기능을 인메모리(adminGymStore)에서 Supabase 영구저장으로
전환하려 한다. 등록/수정/머신연결/목록조회를 모두 Supabase 기반으로 바꾸기 위한
사전 조사. (manager_id는 직접등록 시 null 유지 — 이건 결정됨, 바꾸지 않음)

■ 결과 출력
  D:\시작\gympick\ADMIN_GYM_INVESTIGATION.txt 한 파일에 섹션별로 정리.
  - 각 섹션 "===== [번호] 제목 =====" 구분선
  - 관련 코드는 줄 번호와 함께 그대로 인용 (요약 말고 코드 그대로! 한글 깨짐 방지 위해 Read 사용)
  - 각 섹션 끝 "[분석]"으로 현재 구조/전환 시 고려점 정리
  - 불확실하면 "확인 필요"로 표기 (추측 단정 금지)

⚠ 코드 변경 금지. str_replace / 파일 편집 일절 금지. 결과 파일만 생성.

================================================================================
목표: Supabase gyms 테이블에서 '어드민이 직접등록한 헬스장만' 골라내는 방법 파악.

(3-a) gyms 테이블 읽는 기존 함수
  파일: src/lib/db/gyms.ts
  - fetchGyms / fetchGymsWithMachines 등 gyms 조회 함수들의 select 컬럼 + 반환 타입
  - gyms 테이블에 어떤 컬럼이 있는지 (id, name, location, phone, hours, description,
    latitude, longitude, manager_id 등)

(3-b) gyms insert 형태
  - AdminDashboard handleRegisterGym의 supabase.from('gyms').insert(...) 에서
    넣는 컬럼 목록 (조사 2-a와 연계)

(3-c) 직접등록 식별
  - 직접등록 헬스장을 구분할 방법이 있는지:
    · manager_id IS NULL 로 구분 가능한지 (단, 일반 헬스장도 manager_id null일 수 있음 — 확인)
    · 별도 플래그 컬럼(source, is_admin_registered 등)이 있는지
    · 없다면, 구분 방법이 없다는 사실을 명시 (이 경우 새 컬럼 필요할 수 있음)
  - gyms 테이블 전체 헬스장 중 직접등록만 필터링하는 현실적 방법 정리
