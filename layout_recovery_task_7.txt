확인이나 중단 없이 끝까지 완료해줘.

## 0단계: "운동일지 요약 보기" 버튼 무반응 버그 수정 (다른 작업보다 먼저 처리)

증상: 운동일지 상세화면(하루치 기록 모달)에서 "운동일지 요약 보기" 버튼을 탭해도
아무 반응이 없음.

원인(이미 코드로 확인됨, 추가 조사 불필요): `src/screens/JournalScreen.tsx`에서
이 버튼의 `onOpenSummary` 콜백이 지금 상세화면 모달(`SessionDetailModal`, 즉
`detailSessions` state로 열려있는 `<Modal>`)을 닫지 않은 채로 `summarySession`
state만 바로 세팅해서, `WorkoutLogSummaryModal`의 새 `<Modal>`을 그 위에 그대로
겹쳐서 띄우려고 한다. React Native에서 `<Modal>` 두 개가 동시에 떠 있으면(특히
안드로이드) 나중에 뜨는 쪽이 터치에 반응하지 않거나 아예 화면에 안 뜨는 문제가
있는데, 정확히 이 증상과 일치한다.

실제로 바로 몇 줄 위의 `onOpenMachine` 콜백은 이미 이 문제를 피하려고
"먼저 `setDetailSessions([])`로 상세화면 모달을 닫고, 400ms 뒤에 다음 모달을
연다"는 패턴을 쓰고 있다(`MachineDetailModal`를 열 때). `onOpenSummary`도 이
기존 패턴을 그대로 따라가면 된다. 추측이나 재조사 없이 바로 아래처럼 수정할 것.

`src/screens/JournalScreen.tsx`에서 아래 코드를:
```
onOpenSummary={(session) => setSummarySession(session)}
```
아래처럼 수정한다:
```
onOpenSummary={(session) => {
  setDetailSessions([]);
  setTimeout(() => setSummarySession(session), 400);
}}
```

이 수정 하나로 끝이다. `src/screens/flow/WorkoutLogSummaryModal.tsx`는 이 버그와
무관하니 건드릴 필요 없다. 수정 후 `npx tsc --noEmit`에 에러가 없는지만 확인할 것.

이 0단계는 아래 "사전 확인" 단계에서 말하는 "JournalScreen.tsx는 무관하니 건드리지
말 것"이라는 문구보다 **우선한다** — JournalScreen.tsx는 이번엔 이 0단계 수정
때문에 의도적으로 변경되는 파일이다. 커밋 대상에도 포함시킬 것(아래 6단계 커밋
목록에 `src/screens/JournalScreen.tsx`를 추가해서 함께 커밋).

## 배경

방금 처리한 `layout_recovery_task_6.txt` 작업(커밋 fa768d1)에서, 레이아웃 피커(E
유형/archday/s3~s5) 회귀는 정상 복구했다. 그런데 그 작업 보고서에서 같은 원인
(운동일지 요약화면 편집이 오래된 캐시본을 기준으로 이루어짐)으로 함께 되돌아간
다른 부분들도 발견했다고 했고, 그건 이번 작업 범위가 아니라서 일부러 손대지
않았다고 했다. 이번 작업은 그 나머지 부분들을 같은 방식(진단 → 정확한 원본 위치를
git 히스토리에서 찾기 → 해당 블록만 병합 → 검증 → 커밋/푸시)으로 복구하는 것이다.

지난 작업에서 발견했다고 보고한 4가지:
1. `ExerciseSelectStep`의 "다른 부위도 보기" 프리웨이트 필터칩
2. `PresetScrollRow`(무게/횟수 프리셋 자동 중앙 정렬)
3. 여러 오버레이 컴포넌트의 `fontWeight: Platform.OS === 'android' ? undefined : ...`
   안드로이드 폰트 가드
4. `fontsLoaded` 저장 버튼 가드

파일은 전부 `src/screens/flow/PostWorkoutLogModal.tsx` 안에 있다(지난 작업
보고서 기준). 필요하면 같은 원인으로 `WorkoutCameraOverlay.tsx`에도 영향이
있었는지 함께 확인할 것.

## 중요 — 지난 작업과 다른 점 하나

지금 git HEAD(`fa768d1`)는 지난 작업에서 "레이아웃 피커만" 고쳐서 커밋한
버전인데, 그때 위 4가지는 고치지 않은 채로 파일 전체를 커밋했기 때문에,
**HEAD(`fa768d1`)에도 이 4가지 문제가 그대로 들어있을 수 있다.**
즉 이번엔 `git diff HEAD -- ...` 로는 안 잡힐 수 있다. 각 항목마다
`git log -S"<식별 문자열>" --oneline -- src/screens/flow/PostWorkoutLogModal.tsx`
같은 방식으로 그 코드가 마지막으로 정상적으로 있었던 커밋을 직접 찾아서, 그
커밋의 내용과 지금 내용을 비교해야 한다. 예를 들면:
- `git log -S"다른 부위도 보기" --oneline -- src/screens/flow/PostWorkoutLogModal.tsx`
- `git log -S"PresetScrollRow" --oneline -- src/screens/flow/PostWorkoutLogModal.tsx`
- `git log -S"Platform.OS === 'android' ? undefined" --oneline -- src/screens/flow/PostWorkoutLogModal.tsx`
- `git log -S"fontsLoaded" --oneline -- src/screens/flow/PostWorkoutLogModal.tsx`

## 절대 하지 말 것

- 파일 전체를 특정 커밋으로 되돌리는 방식(`git checkout <커밋> -- 파일`) 금지.
  4가지 항목에 해당하는 코드 블록만 정확히 골라서 병합할 것.
- `buildComparisonCard`, `ComparisonCard`, `WorkoutDoneStep` 함수, 그 안의
  `export` 처리, 그리고 관련 스타일(`sum*`, `comp*`, `bar*`, `rowsHeader*`,
  `col*`)은 절대 건드리지 말 것 — 이건 최근에 추가된 "운동일지 요약화면" 기능
  코드이고 위 4가지 문제와 무관하다.
- `src/screens/JournalScreen.tsx`는 위 0단계 수정(딱 그 한 군데)만 반영하고,
  그 외에는 절대 손대지 말 것. `src/screens/flow/WorkoutLogSummaryModal.tsx`는
  이번 작업(0단계 포함) 전체와 무관하니 절대 건드리거나 되돌리지 말 것
  (git status에 수정/신규로 보여도 그냥 둘 것, 커밋 대상 아님).
- 4가지 중 어느 하나라도 git 히스토리에서 명확한 원본을 못 찾겠으면, 추측해서
  새로 만들지 말고 그 항목만 "못 찾음"으로 보고하고 나머지만 처리할 것.
- `git add -A` / `git add .` 금지. 실제로 수정한 파일명만 정확히 나열해서 add할 것.

## 진행 순서

1. 위 4가지 각각에 대해 git 히스토리에서 정상 버전이 있던 커밋을 찾는다.
2. 그 커밋의 해당 블록과 지금 작업 트리의 같은 위치를 비교(diff)해서, 정확히
   어떤 코드가 어떻게 달라졌는지 확인한다.
3. 지금 작업 트리 파일에서 그 블록만 정상 버전으로 교체한다. 나머지(운동일지
   요약화면 관련 코드, WorkoutLogSummaryModal.tsx, 그리고 0단계에서 이미 고친
   부분 외의 JournalScreen.tsx)는 손대지 않는다.
4. `npx tsc --noEmit` 실행 — 에러 있으면 원인 파악 후 수정(추측 금지).
5. 아래로 최종 검증:
   - 0단계 버튼 수정이 정확히 반영됐는지 `grep -n "onOpenSummary"
     src/screens/JournalScreen.tsx` 로 확인
   - 복구한 4가지 코드가 실제로 파일에 들어와 있는지 각각 grep으로 확인
   - `grep -n "buildComparisonCard\|ComparisonCard\|WorkoutDoneStep"
     src/screens/flow/PostWorkoutLogModal.tsx` 로 요약화면 코드가 그대로인지 확인
   - `git status` 로 변경 파일이 예상(`PostWorkoutLogModal.tsx`,
     `src/screens/JournalScreen.tsx`, 필요시 `WorkoutCameraOverlay.tsx`)과
     일치하는지 확인. `WorkoutLogSummaryModal.tsx`, task*.txt류는 변경/신규로
     보여도 그대로 둘 것(커밋 대상 아님).
6. 문제 없으면:
   - `git add src/screens/flow/PostWorkoutLogModal.tsx src/screens/JournalScreen.tsx`
     (해당 시 `WorkoutCameraOverlay.tsx`도) — 정확히 이 파일명들만.
   - 커밋 메시지: "fix: 운동일지 요약 보기 버튼 무반응 수정 + 되돌아간 나머지 항목 복구 (필터칩/프리셋 정렬/안드로이드 폰트 가드/fontsLoaded 가드)"
   - `git push`
