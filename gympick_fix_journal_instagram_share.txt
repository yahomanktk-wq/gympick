BACKGROUND
==================================================

This is a follow-up to gympick_fix_media_permission_policy.txt. That task
already changed MediaLibrary.requestPermissionsAsync() to
requestPermissionsAsync(true) (writeOnly) across the app, since the app's
READ_MEDIA_IMAGES/READ_MEDIA_VIDEO permissions are now blocked via
expo-build-properties to satisfy Google Play policy.

However, handleInstagramShare in src/screens/JournalScreen.tsx still calls
MediaLibrary.getAssetsAsync(...) right after saveToLibraryAsync(...), purely
to retrieve the asset id of the file it just saved (needed for the iOS
Instagram deep link). getAssetsAsync is a read/query operation and will not
work reliably now that read permission is no longer declared/granted.

The fix: replace the saveToLibraryAsync + getAssetsAsync pair with a single
call to MediaLibrary.createAssetAsync(uri), which saves the file AND returns
the Asset object (including .id) directly — no read permission needed. This
exact pattern is already used successfully in handleInstagramShare inside
src/screens/flow/PostWorkoutLogModal.tsx; mirror that approach here.
