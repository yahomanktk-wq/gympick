# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

`src/screens/flow/PostWorkoutLogModal.tsx`에서 운동일지 작성 중 "머신 선택" 스텝의
구조를 조사한다. 목표 기능: 이 화면에 "머신 ↔ 프리웨이트" 토글 버튼을 추가해서,
토글에 따라 머신 카드 그리드와 프리웨이트 카드 그리드를 전환해서 보여주는 것.
이 조사는 그 설계를 위한 사전 파악이며, 코드는 수정하지 않는다.

## 조사 항목

### 1. 머신 선택 스텝 컴포넌트 구조

- 머신 선택이 이루어지는 스텝(컴포넌트 함수)의 이름과 시작/끝 줄 번호
- 이전 대화에서 확인된 호출부 4곳(980, 1042, 1107, 1152번째 줄 근처 `<MachineCard ...>`)이
  각각 어떤 상황(새 루틴 작성 / 이전 루틴 참고 / 헬스장 추천 루틴 / 다른 유저 루틴 등)에
  대응하는지, 그리고 그중 어디에 프리웨이트 항목이 이미 섞여서 렌더링되고 있는지
  (1152번째 줄 근처가 "Free Weight 항목, machine 인라인 객체 구성"이라고 조사된 바 있음 —
  정확한 코드와 조건문 전체 확인)

### 2. 프리웨이트 데이터가 현재 어떻게 다뤄지는지

- `FreeWeightExercise` 타입 정의 위치와 필드 구성
- `FREE_WEIGHTS` 상수와 `dbFreeWeights` 변수가 각각 어디서 정의/조회되는지, 서로 다른
  경우 어떤 우선순위로 쓰이는지 (`dbFreeWeights.length > 0 ? dbFreeWeights : FREE_WEIGHTS`
  패턴이 앞서 조사에서 발견된 바 있음 — 정확한 위치와 전체 문맥 확인)
- 현재 화면에서 머신 카드와 프리웨이트 카드가 "하나의 리스트에 섞여서" 렌더링되는지,
  아니면 이미 별도 섹션으로 나뉘어 있는지 (예: 스크롤하면 머신들 지나서 프리웨이트가
  나오는 구조인지)
- 프리웨이트 항목을 렌더링할 때 `MachineCard`를 그대로 재사용하는지, 아니면 별도
  컴포넌트를 쓰는지

### 3. 이 스텝에 이미 있는 필터/검색 UI 확인

- 부위(target muscle) 필터, 브랜드 필터, 검색창 등이 이 스텝에 이미 있는지
- 있다면 그 필터들이 머신에만 적용되는지, 프리웨이트 항목에도 같은 필터 로직이
  걸리는지 (예: 프리웨이트도 targetMuscle 필드가 있어서 부위 필터에 걸리는지)
- 필터/검색 UI의 정확한 위치(줄 번호)와 상태 변수명들

### 4. 현재 스텝의 상태(state) 관리 구조

- 이 스텝 컴포넌트가 관리하는 주요 state 변수 목록 (선택된 머신 id들, 검색어, 필터 값 등)
- 머신 선택과 프리웨이트 선택이 결과적으로 같은 곳(`logs`, `selectedExercises` 등)에
  합쳐져서 저장되는지, 아니면 별도로 관리되다가 나중에 합쳐지는지

### 5. 기존 앱의 다른 화면에서 쓰인 토글 UI 패턴 예시 확인

- `AdminDashboard.tsx`의 `regGymToggleRow` / `regGymToggleChip` 스타일 (전체/선택됨 토글)
  코드를 참고용으로 다시 한 번 정확히 확인 (그대로 재사용할 수 있는 패턴인지 판단 목적)

## 출력 형식

- 각 항목에 대해 파일 경로 + 정확한 줄 번호 + 코드 그대로
- 마지막에 "머신 선택 스텝의 현재 렌더링 흐름"을 간단한 트리/순서로 요약
