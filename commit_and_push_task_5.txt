최근 세션들에서 수정된 아래 8개 파일만 정확히 커밋하고 원격에 푸시한다.

## 1단계 — 사전 확인
`git status`를 실행해서 변경 내역을 확인한다. 다음 8개 파일이 modified로
나와야 한다:
- src/lib/db/workouts.ts
- src/screens/HomeScreen.tsx
- src/screens/WorkoutFeedScreen.tsx
- src/screens/flow/PostWorkoutLogModal.tsx
- src/screens/flow/WorkoutCameraOverlay.tsx
- app.json
- package.json
- src/screens/ProfileScreen.tsx

- untracked(새 파일)로 commit_message_task_4.txt, commit_and_push_task_5.txt가
  보일 수 있는데, 이 두 파일은 .gitignore의 `*_task.txt` / `task*.txt` 패턴에
  걸려서 git status에 아예 안 보이는 게 정상이다 — 혹시 보이더라도 절대
  커밋 대상에 포함하지 말 것.

위 8개 파일 외에 의도치 않은 다른 변경사항이나 새 파일이 섞여 있다면(예:
다른 작업 세션에서 아직 커밋 안 된 별도 수정사항 등), 절대 임의로 판단해서
같이 커밋하지 말고, 어떤 파일들이 더 있는지 목록으로 보고하고 멈출 것.
반대로 위 8개 중 일부가 이미 git status에 없다면(=이미 커밋된 상태라면),
그 사실을 그대로 보고하고 남아있는 파일만 진행할 것.

app.json의 "version"이 "1.2.3", ios.buildNumber가 "41", android.versionCode가
22인지, package.json의 "version"도 "1.2.3"인지 확인할 것. 다르면 멈추고 보고.

## 2단계 — 잔여 하드코딩 버전 문자열 확인
src/ 전체에서 "1.2.2" 및 "1.1.7" 문자열을 검색해서, ProfileScreen.tsx의
버전 표시 텍스트 외에 다른 곳에도 구버전이 하드코딩되어 있는지 확인한다.
발견되면 무엇을 발견했는지 보고만 하고, 이번 커밋 범위에 임의로 포함시켜
수정하지 말 것 (별도 확인 후 처리).

## 3단계 — 타입체크
`npx tsc --noEmit`으로 타입 에러가 없는지 확인한다. 에러가 있다면 무엇인지
보고하고 커밋을 진행할지 물어볼 것 (임의로 수정하지 말 것).

## 4단계 — 스테이징
아래 8개 파일만 정확히 add한다. `git add -A`나 `git add .`는 절대 사용하지
말 것 (1단계에서 확인된 파일 중 실제로 git status에 존재하는 파일만 add).

```
git add src/lib/db/workouts.ts src/screens/HomeScreen.tsx src/screens/WorkoutFeedScreen.tsx src/screens/flow/PostWorkoutLogModal.tsx src/screens/flow/WorkoutCameraOverlay.tsx app.json package.json src/screens/ProfileScreen.tsx
```

## 5단계 — 커밋
레포 루트에 이미 준비되어 있는 커밋 메시지 파일을 사용한다 (직접 -m으로
타이핑하지 말 것):

```
git commit -F commit_message_task_4.txt
```

## 6단계 — 푸시
```
git push
```
