[조사 전용 태스크 — 코드 수정 금지, 읽기 전용 조사만 수행]

이 파일을 읽고 확인이나 중단 없이 끝까지 완료해줘.

## 배경
머신·헬스장 찾기 화면(FindGymScreen)의 머신카드 그리드에서, 이미지 변환
(getMachineImageUrl, IMAGE_TRANSFORM_ENABLED=true) 적용 후 머신 이미지가
비정상적으로 확대/크롭되어 출력됨. 카드 안에서 원래는 여백을 두고 작게
보이던 머신이, 이제는 카드를 거의 꽉 채우면서 위아래가 잘리고 텍스트와
겹쳐 보임.

반면 같은 카드를 탭해서 들어가는 상세화면(MachineDetailModal 등, 원본
URL 그대로 사용하는 화면)은 정상적으로 보임 — 즉 변환된 이미지에서만
발생하는 문제로 추정됨.

## 조사 범위

### 1. MachineCard.tsx / MachineCardBorder.tsx의 이미지 렌더링 방식 확인
- 이미지 컴포넌트의 contentFit / resizeMode 값이 무엇인지 (cover vs contain)
- 이미지를 담는 컨테이너의 실제 가로/세로 비율(aspect ratio)과 고정
  width/height 스타일 값 확인
- MachineCard가 원본 800×800 이미지를 어떤 비율의 박스에 넣고 있었는지
  (그리드 variant 기준)

### 2. getMachineImageUrl 호출부에서 실제 넘기는 width 값 확인
- FindGymScreen.tsx의 MachineItem에서 getMachineImageUrl(machineId,
  { width: cardWidth * 2 })로 호출할 때, cardWidth의 실제 계산값(픽셀)이
  얼마인지, 그리고 이때 height 파라미터는 넘기지 않는다는 것을 재확인
- 실제로 생성되는 render URL 예시를 하나 만들어서 (예:
  .../render/image/public/machine-images/xxx.webp?width=320&quality=75)
  기록해둘 것

### 3. 원본 이미지 파일 자체의 실제 비율 확인
- Supabase Storage의 machine-images 버킷에서 문제가 된 머신(스크린샷 속
  "LATERAL RAISE", "REAR DELT PEC FLY" 등 Nautilus 브랜드 머신)의 원본
  webp 파일을 하나 다운로드하거나 메타데이터를 확인해서, 실제 가로:세로
  비율이 정확히 1:1(800×800)인지, 아니면 그 안에 여백이 있어 시각적으로만
  사각형이고 실제 파일은 다른 비율인지 확인
  (다운로드 후 이미지 실제 픽셀 크기 측정, 또는 Supabase 대시보드에서
  파일 정보 확인)

### 4. Supabase Image Transformation의 기본 동작 방식 재확인
- width만 주고 height를 안 줬을 때 기본 resize 모드(cover)가 실제로 어떻게
  동작하는지 — 크롭이 발생하는 조건이 무엇인지
- 브라우저에서 직접 변환 URL에 파라미터를 바꿔가며 테스트해볼 것
  (코드 수정 없이, 브라우저 주소창 테스트만):
  - `?width=320&quality=75` (현재 상태, 문제 재현)
  - `?width=320&height=320&quality=75&resize=contain` (height 명시 +
    contain 모드)
  - `?width=320&quality=75&resize=contain` (contain 모드만 추가)
  각 URL을 브라우저에 직접 붙여넣어서 응답 이미지가 어떻게 다르게 보이는지
  스크린샷 없이 텍스트로 차이를 설명 (이미지 크기, 잘림 여부)

## 출력 형식
1. MachineCard/MachineCardBorder의 contentFit/resizeMode 및 컨테이너 비율
2. FindGymScreen에서 실제 요청되는 width 값과 완성된 render URL 예시
3. 원본 머신 이미지 파일의 실제 픽셀 비율 (정사각형이 맞는지 여부)
4. resize=contain 등 파라미터를 바꿨을 때 문제가 해결되는지 여부
5. 위 조사를 바탕으로, 크롭이 발생하는 정확한 원인 한 문장 요약과
   가장 가능성 높은 해결 방향 1~2가지 제안 (코드 수정은 하지 말고
   "이렇게 고치면 될 것 같다"는 제안까지만)

코드는 절대 변경하지 마. 조사 결과만 텍스트로 정리해서 보고해줘.
