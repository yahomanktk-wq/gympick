[1] 온보딩 16~18단계 자동 스크롤 추가

대상 파일: PostWorkoutLogModal.tsx (WorkoutPhotoStep 영역, 메인 ScrollView 약 L2643)

현재 구조:
- L2366~2422 useEffect가 onboardingKey가 'photo-overlay' / 'photo-color' /
  'photo-save-share'로 바뀔 때 overlayStyleRef / colorChipRef / shareRowRef에
  measureInWindow를 호출해서 스포트라이트 좌표를 계산함.
- L2643의 메인 ScrollView에는 ref가 없어서, 해당 요소가 화면 밖에 있으면
  스포트라이트가 화면 밖 좌표를 가리키게 됨 (현재 버그 원인).

수정 방향:
1. WorkoutPhotoStep 영역에 photoScrollRef (useRef<ScrollView>(null)) 를 새로
   선언하고, L2643 ScrollView에 ref={photoScrollRef} 를 달아줘.

2. 기존 useEffect(L2366~2422)에서 onboardingKey가 'photo-overlay' / 'photo-color'
   / 'photo-save-share' 중 하나로 바뀔 때, 기존 measureInWindow 호출 전에
   다음을 먼저 수행해줘:
   - 해당 ref(overlayStyleRef / colorChipRef / shareRowRef)에
     measureLayout(findNodeHandle(photoScrollRef.current), ...) 을 호출해서
     ScrollView 콘텐츠 기준 y좌표를 구함
   - photoScrollRef.current?.scrollTo({ y: 구한 y값 - 적당한 상단 여백(40~60),
     animated: true }) 로 스크롤

3. 스크롤 애니메이션이 끝난 뒤(예: setTimeout 350~400ms, 또는
   onMomentumScrollEnd 활용) 기존 measure() 로직(measureInWindow 기반
   스포트라이트 좌표 계산)을 실행해줘. 스크롤 도중에 measureInWindow를 부르면
   좌표가 부정확하니, "스크롤 완료 → 재측정" 순서를 반드시 지켜줘.

4. 다른 onboarding 단계(특히 L1210의 별도 scrollRef를 쓰는 세트 기록 단계)는
   절대 건드리지 마. 이 수정은 photo-overlay / photo-color / photo-save-share
   세 단계에만 적용되는 거야.

수정 전/후 코드를 빠짐없이 보여주고, useEffect 의존성 배열이나 클린업이
꼬이지 않는지 한 번 더 확인해줘.
