================================================================================
[정리] 디버깅용 console.log 삭제 (인증샷 저장 함수)
================================================================================

■ 목적
인증샷 저장 시 터미널에 거대한 객체(routineCardRef.current 등 React 내부 구조)가
출력되는 디버깅용 console.log 5줄을 제거한다. 운영 성능/노이즈 개선.

■ 매우 중요 — 안전 범위
- 오직 아래 명시된 console.log 5줄만 삭제한다.
- console.error / console.warn 은 절대 건드리지 말 것 (실패 진단용으로 보존).
- 실제 동작 코드(captureRef, saveToLibraryAsync, 변수 선언 등)는 일절 건드리지 말 것.
- console.log는 출력만 하는 함수라 삭제해도 기능에 영향이 없다.

■ 변경 파일
  src/screens/flow/PostWorkoutLogModal.tsx

⚠ Windows(CRLF) 가능 — str_replace 실패 시 Read로 확인 후 맞출 것.

================================================================================
[삭제] handleSaveImage 함수 시작부의 디버깅 log 5줄 (대략 L2554~2558)
================================================================================
아래 5줄을 찾아서 '그 5줄만' 삭제한다 (위아래 다른 코드는 그대로 유지).

삭제 대상:
    console.log('[handleSaveImage] called');
    console.log('[handleSaveImage] photoUri:', photoUri);
    console.log('[handleSaveImage] overlayRef.current:', overlayRef.current);
    console.log('[handleSaveImage] textColor:', textColor);
    console.log('[handleSaveImage] routineCardRef:', routineCardRef.current);

처리 방법:
- 위 5줄을 빈 줄 없이 통째로 제거 (5줄 삭제).
- 이 5줄 바로 위/아래의 다른 코드(함수 선언, 변수, 캡처 로직 등)는 절대 건드리지 말 것.
- str_replace로 위 5줄 블록을 빈 문자열로 교체하거나, 각 줄을 개별 삭제.

================================================================================
[보존] 아래는 절대 삭제/변경하지 말 것
================================================================================
- console.error(...) 전부 (L2596, 2609, 2633, 2654, 2669, 2702, 2707 등)
  → 캡처/공유 실패 시에만 출력되는 진단 로그. 운영에 유용. 보존.
- console.warn(...) 전부 (L2657, 2681, 4156 등, 그리고 __DEV__ 가드된 것들)
  → 보존.
- captureRef, MediaLibrary.saveToLibraryAsync, 변수 선언(photoUri/textColor/
  overlayRef/routineCardRef 등) → 실제 동작 코드. 절대 보존.

================================================================================
■ 완료 후 자체 점검
================================================================================
1) npx tsc --noEmit → 신규 에러 0건
   ※ 혹시 '미사용 변수' 경고가 새로 뜨면(로그에서만 쓰이던 변수가 있었을 경우),
     그 변수가 다른 곳에서도 쓰이는지 확인. 실제로는 overlayRef/routineCardRef/
     photoUri/textColor 모두 캡처 로직에서 쓰이므로 미사용이 되지 않아야 정상.
     만약 경고가 뜨면 보고만 하고 변수 자체는 삭제하지 말 것(기능에 쓰일 수 있음).
2) 삭제된 것은 console.log 5줄뿐인지 (console.error/warn 개수는 그대로인지) 확인
3) 위 5줄 외 어떤 코드도 변경되지 않았는지 확인

■ 사람이 직접 할 일 (동작 테스트)
- 운동일지 작성 → 인증샷 저장 → 정상 저장되는지 (기능 동일한지)
- 인스타그램 공유 → 정상 공유되는지
- 터미널에 거대한 routineCardRef 객체 로그가 더 이상 안 나오는지
※ 기능이 이전과 100% 동일해야 정상 (console.log는 출력만 하던 것이라 기능 무관).
