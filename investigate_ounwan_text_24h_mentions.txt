# 목적 (읽기 전용 조사 — 코드 수정 절대 금지)

두 가지를 조사한다. 코드는 수정하지 않는다.

A. HomeScreen의 "오늘의 오운완" 섹션 헤더 텍스트가 정확히 어떤 로직으로 만들어지는지
   확인 (폴백으로 24시간 이전 게시물이 섞여 나올 수 있게 됐으므로, 지금 텍스트가
   실제 상황과 안 맞을 수 있음 — 정확한 현재 코드를 확인하는 것이 목적).

B. 앱 전체에서 "24시간"이라는 시간 제약을 사용자에게 안내/암시하는 텍스트나 UI가
   또 있는지 전수 조사 (오운완 폴백 이후에도 여전히 유효한 안내인지, 아니면 이제
   부정확해진 문구인지 판단하기 위함).

## 조사 항목

### A. HomeScreen 헤더 텍스트

- `src/screens/HomeScreen.tsx`의 `OunwanHeader` 컴포넌트와 그 `message` prop을
  계산하는 부분 전체 코드 (정확한 줄 번호 포함). 조사에서 이전에 언급된 형태:
  "오늘 {부위} 운동한 사람들이에요! 💪" / "오늘 운동한 사람들이에요! 💪" — 실제
  현재 코드로 재확인
- 이 메시지가 `ounwanDisplayTarget` 등 어떤 상태값에 의존하는지, 그 상태값이
  게시물의 실제 시간 범위(24시간 vs 폴백된 전체)와는 무관하게 계산되는지 확인
- 폴백이 발동했는지 여부(즉 `posts.length < 3`이라 넓혀서 조회했는지)를 현재
  컴포넌트가 알 수 있는 상태값이 있는지, 없다면 어떻게 추가할 수 있을지 참고용으로
  확인 (예: 별도 boolean state를 만들어야 하는지)

### B. "24시간" 관련 문구 전수 검색

- 프로젝트 전체(`src/`)에서 "24시간", "24h", "하루", "오늘" 등의 문자열을 grep해서,
  사용자에게 보이는 UI 텍스트(Text 컴포넌트 안의 문자열, Alert 메시지 등) 중
  오운완/피드와 관련된 것을 전부 찾는다. 특히 다음을 확인:
  - `src/screens/WorkoutFeedScreen.tsx`의 "N시간 후 사라져요" / "곧 사라져요" 카운트다운
    문구 (이전 조사에서 154~162번째 줄 근처로 확인된 부분) — 이 문구가 표시되는
    게시물이 실제로 폴백을 통해 노출된 게시물(24시간이 지난 것)일 경우, "이미 지난
    시각" 같은 음수/이상한 값이 나올 수 있는지 로직을 확인 (`diffH >= 24`일 때
    `return '곧 사라져요';`로 처리된다고 조사되었는데, 실제로 이게 몇 시간까지
    지속되든 항상 "곧 사라져요"로만 표시되는지, 아니면 다른 이상 동작이 있는지)
  - 온보딩 화면, 툴팁, 안내 문구 등에도 "24시간" 관련 텍스트가 있는지
    (`src/screens/` 전체와 컴포넌트 폴더까지 포함해서 grep)
  - 운동일지 작성 완료 후(`PostWorkoutLogModal.tsx`) 오운완 업로드 시 사용자에게
    보여주는 안내 문구 중에도 "24시간 동안 공개된다" 류의 텍스트가 있는지

## 출력 형식
