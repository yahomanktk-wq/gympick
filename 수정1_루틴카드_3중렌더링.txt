## 배경
조사 결과, PostWorkoutLogModal.tsx의 "photo" 스텝(루틴카드 생성 단계)에서
동일한 800×800 머신 이미지가 화면 하나에서 최소 2~3번 별도로 렌더링되고
있음이 확인됨:

1. 실제 사용자에게 보이는 루틴카드 미리보기 (라인 ~3010)
2. 화면 밖(top: -9999 등으로 숨겨진) 행 높이 측정용 뷰 (라인 ~3076)
3. 인스타 공유용 루틴카드 캡처 뷰 — 멀티 페이지면 페이지 수만큼 반복 (라인 ~3151)

이 중 2번(측정용 뷰)은 사용자 눈에 전혀 보이지 않는데도 이미지를 실제로
다운로드하고 있어 완전히 불필요한 트래픽 낭비이며, 운동 기록은 앱에서
가장 빈번한 핵심 동작이라 이 부분의 개선 효과가 가장 클 것으로 판단됨.

또한 3곳 모두 react-native 기본 Image 컴포넌트를 쓰고 있어 캐싱이 약함
(expo-image가 아님 — expo-image는 memory-disk 캐시를 지원하지만 RN 기본
Image는 디스크 캐시가 거의 없음).

## 목표
1. 측정용 뷰(2번)가 실제 이미지 다운로드를 유발하지 않도록 수정
   - 이미지 없이 텍스트/레이아웃만으로 행 높이를 측정할 수 있는지 먼저 확인
   - 불가능하다면, 이미 로드된 이미지(1번 미리보기)의 캐시를 재사용하도록 하거나,
     최소한 RN 기본 Image 대신 expo-image로 바꿔서 같은 URL이면 디스크 캐시를
     타도록 만들 것 (완전히 안 보이는 뷰에서 별도 네트워크 요청이 발생하지
     않는 것이 최우선 목표)
2. 나머지 렌더링 지점(1번, 3번)도 RN 기본 Image → expo-image로 교체
   (cachePolicy="memory-disk" 적용)
3. 세 군데가 동일한 machineId 목록을 참조하고 있다면, 같은 URL의 이미지가
   expo-image 캐시를 통해 재사용되는지 확인 (같은 URL이면 최초 1회만 실제
   네트워크 요청이 발생해야 함)

## 절대 지키기
- MachineCard.tsx 구조는 건드리지 말 것 (이 파일은 MachineCard를 직접 쓰지
  않는 별도 루틴카드 렌더링 로직이므로 무관하지만, 혹시 참조하는 부분이
  있다면 구조 변경 없이 이미지 로딩 방식만 수정)
- 루틴카드의 시각적 결과물(레이아웃, 캡처 이미지 품질)은 기존과 동일해야 함
  — 이번 수정은 순수하게 "같은 이미지를 몇 번 다운로드하느냐"의 문제만 고침
- 기능별로 모듈화: 만약 이미지 로딩 관련 공통 로직이 필요하다면 새 파일로
  분리 (PostWorkoutLogModal.tsx 안에 전부 넣지 말 것)
- 변경 범위가 예상보다 커지거나(예: 측정용 뷰 자체를 다른 방식으로 완전히
  재설계해야 하는 경우) 애매하면, 진행 전에 먼저 나에게 알려줘
