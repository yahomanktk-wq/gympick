[B] AdminDashboard 매니저 신청 목록 — Supabase 연동 (실제로 코드 수정)

현재 AdminDashboard의 매니저 신청 관리 화면이 managerApplicationStore.ts의
로컬 인메모리 데이터(getAllManagerApplications())만 표시하고 있음.
실제 Supabase manager_requests 테이블의 데이터를 읽도록 수정해줘.

1. AdminDashboard.tsx에서 매니저 신청 목록을 로드하는 부분을 찾아줘.
2. getAllManagerApplications() 대신 Supabase에서 manager_requests 테이블을
   직접 조회하도록 변경해줘:
   - 테이블: manager_requests
   - 필드: id, user_id, gym_name, location, phone, message, status, created_at
   - status가 'pending'인 것 우선, 나머지도 표시
3. ManagerApplication 타입과 매핑이 맞지 않으면 적절히 변환해줘.
4. 승인/거절 액션(updateApplicationStatus)도 Supabase를 실제로 업데이트하도록
   확인하고, 로컬만 업데이트하고 있다면 Supabase도 같이 업데이트하도록 수정해줘.
5. 수정 전/후 보여줘.

[F] 헬스장 상세화면 주소 끝 ", Seoul" 접미사 에러 수정 (실제로 코드 수정)

증상: GymDetailModal의 정보 탭에서 모든 헬스장 주소 끝에 ", Seoul"이 붙어 표시됨.
예: "대전광역시 서구 대덕대로 226 명동프라자 2층 헬스보이짐, Seoul"
(해당 헬스장은 대전 소재이므로 Seoul은 완전히 잘못된 정보)

원인 조사 및 수정:
1. GymDetailModal.tsx에서 주소(location)를 표시하는 코드를 찾아줘.
   혹시 gym.location 외에 geocoding 결과나 다른 주소 필드를 조합해서
   표시하는지 확인해줘.

2. lib/geocoding.ts의 geocodeAddress 함수를 찾아서 반환값을 확인해줘.
   이 함수가 주소 문자열을 반환하는 경우, 그 문자열에 ", Seoul"이
   포함될 수 있는지 확인해줘.

3. Supabase의 gyms 테이블에서 location 컬럼에 실제로 ", Seoul"이 저장되어
   있는지 확인하는 SQL을 제안해줘 (직접 실행은 못하지만, 결과를 보고
   판단할 수 있도록).

4. 원인이 발견되면 즉시 수정해줘:
   - GymDetailModal에서 주소 표시 시 ", Seoul" 등 불필요한 suffix를
     제거하는 처리 추가 (예: location.replace(/, Seoul$/i, '').trim())
   - 또는 근본 원인(geocoding 함수가 주소를 변경하는 경우)을 수정

5. 수정 전/후 보여줘.
