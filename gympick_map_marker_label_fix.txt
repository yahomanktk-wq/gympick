[배경 — 확정된 원인]
GymMapView.tsx의 마커 라벨(markerText 스타일)이 maxWidth: 80에 numberOfLines={1}만
설정되어 있고 ellipsizeMode는 미설정(RN 기본값 'tail')인 상태. 한글 긴 이름이 80dp를
초과하면 "..."로 줄어드는 게 아니라 한두 글자만 남고 그냥 잘려버림. 원인은
react-native-maps의 커스텀 마커가 안드로이드에서 네이티브 비트맵으로 스냅샷되는 방식이라,
Text의 ellipsizeMode 처리가 이 과정에서 안정적으로 적용되지 않는 것으로 보임 (라이브러리
레벨의 알려진 한계).

해결 방향: 네이티브의 ellipsizeMode에 의존하지 않고, JS 코드에서 직접 글자 수를 잘라
"..."을 붙이는 방식으로 바꾼다 — 렌더링 방식과 무관하게 항상 결과가 보장됨.


[1] 헬스장 이름을 JS 레벨에서 자르는 헬퍼 추가 및 적용 (실제로 코드 수정)

GymMapView.tsx에서:

1. 모듈 레벨(컴포넌트 함수 바깥)에 간단한 헬퍼 함수를 추가해줘:
   function truncateGymName(name: string, maxLen: number): string {
     return name.length > maxLen ? name.slice(0, maxLen) + '…' : name;
   }
   (… 문자는 마침표 세 개 대신 단일 줄임표 문자 사용 — 자간 차지가 적음)

2. 마커의 <Text>에 gym.name을 그대로 넣는 대신, truncateGymName(gym.name, 6) 처럼 적당한
   글자 수로 잘라서 넣어줘. 글자 수는 한글 기준으로 markerText의 실제 표시 가능 너비에 맞춰
   조정해줘 — 너무 길어서 다시 잘리는 일이 없도록, 기존 maxWidth: 80 안에 6~7자 정도가
   들어가는지 가늠해서 정해줘 (정확한 숫자는 코드 작성자가 판단해서 정하면 됨, 너무
   타이트하지 않게 약간 여유를 두는 게 안전함).

3. numberOfLines={1}은 그대로 유지하고, ellipsizeMode="clip"으로 명시적으로 바꿔줘
   (이미 JS에서 자르기 때문에 네이티브 "..." 처리는 더 이상 필요 없고, 혹시 모를 추가
   잘림이 생겨도 어색한 부분 문자 없이 깔끔하게 잘리도록).

4. markerText 스타일의 maxWidth는 약간 여유 있게 조정해줘 (예: 80 → 100 정도, 정확한 값은
   판단해서 정해도 됨) — JS 자르기와 maxWidth 둘 다 안전망 역할을 하도록.

이 변경은 GymMapView.tsx의 마커 렌더링 부분에만 적용하고, 다른 곳(리스트 화면 등 헬스장
이름을 보여주는 다른 컴포넌트)은 건드리지 마 — 거기는 이미 정상 표시되고 있음.
