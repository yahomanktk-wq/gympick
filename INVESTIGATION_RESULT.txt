===== [1] 이전 수행세션(무게×횟수) 값 표시 여부 =====

■ 세트 입력칸 초기값
초기값은 빈칸이 아니라 고정 기본값 { weight: 60, reps: 10 } 이다.

관련 코드 — PostWorkoutLogModal.tsx L3718-3721:
  setLogs(prev => ({
    ...prev,
    [id]: prev[id]?.length ? prev[id] : [{ weight: 60, reps: 10 }],
  }));

동작 설명:
  - 같은 세션 내에서 동일 머신을 다시 열면 prev[id]?.length 조건으로 기존 기록이 유지된다.
  - 그러나 '이전 워크아웃(다른 날 세션)'의 마지막 세트를 불러오는 코드는 없다.
  - 즉, 새 세션을 시작할 때마다 항상 60 kg × 10 reps 로 초기화된다.

■ 이전 기록 조회 코드 존재 여부
  - 없음. fetchWorkoutLogs, fetchWorkoutSets 등 어디에도 "이 머신의 마지막 세트" 를
    조회해서 초기값으로 세팅하는 로직이 없다.
  - HIST_PRS(L87) 는 getMachinePRsFull(MOCK_SESSIONS) 로 "최고 기록(PR)" 만 갖고 있으며,
    세트 입력칸 초기값에 사용되지 않는다.
  - SetCard L1101-1105 에서 histPR 이 있으면 "내 PR" 배지를 보여주지만,
    이것은 참조용 표시일 뿐 입력칸 값을 채워주지 않는다.
    관련 코드:
      {histPR && (
        <View style={s.yourPRRow}>
          <Text style={s.yourPRLabel}>내 PR</Text>
          <Text style={s.yourPRVal}>{histPR.weight} kg × {histPR.reps}</Text>
        </View>
      )}

■ 과거 세트 조회 데이터 경로 가능 여부
  - workout_sets 테이블은 Supabase에 존재하며 fetchWorkoutSets 함수도 있다.
  - 그러나 "특정 머신의 가장 최근 세트" 를 필터링하는 API/함수가 현재 없다.
  - 구현하려면 machineId 기준으로 workout_entries → workout_sets 를 JOIN 조회해야 한다.

[분석]
  - 현재 동작: 세트 입력칸 초기값은 항상 60 kg × 10 reps (고정).
  - 이전 기록 프리필 기능 미구현. PR 배지만 참조용으로 표시됨.
  - 관련 위치: PostWorkoutLogModal.tsx L3718-3721 (초기값 세팅), L1101-1105 (PR 배지 표시)

===== [2] 부위 선택 시 'Other' 부위 머신도 함께 표시되는지 =====

■ matchesMuscle 전체 코드 (PostWorkoutLogModal.tsx L732-738)
  function matchesMuscle(targetMuscle: string): boolean {
    if (selectedMuscles.has(targetMuscle)) return true;
    if (targetMuscle === 'Glutes' && selectedMuscles.has('Hip (Glutes)')) return true;
    if (targetMuscle === 'Glutes' && selectedMuscles.has('Leg')) return true;
    return false;
  }

■ 'Other' 머신 개수와 예시
  기계 데이터(src/data/machines.ts)에서 targetMuscle: 'Other' 인 머신: 총 52개 이상.

    (이외 40+ 개 - SMITH MACHINE, FUNCTIONAL TRAINER, 복근기구 등)

■ MUSCLE_GROUPS에 'Other' 카드 있는지
  없음. L188-195에 정의된 6개만 있다:
    Chest, Back, Shoulder, Arms, Leg, Hip (Glutes)
  'Other' 카드가 없으므로 사용자가 'Other' 부위를 선택할 방법 자체가 없다.

  어떤 부위를 선택하든 노출되지 않는다.

■ 'Other'를 항상 포함하려면 어디를 고쳐야 하는지
  PostWorkoutLogModal.tsx L732-738 matchesMuscle 함수.
  현재 return false; 바로 위에
    if (targetMuscle === 'Other') return true;
  한 줄을 추가하면 어느 부위를 선택하든 'Other' 머신이 함께 표시된다.

[분석]
  - 현재 동작: 'Other' 머신은 어떤 부위를 선택해도 목록에 나타나지 않는다.
  - 원인: MUSCLE_GROUPS에 'Other' 카드 없음 → selectedMuscles에 'Other' 진입 불가.
    + matchesMuscle에 'Other' 처리 로직 없음.
  - 수정 위치: matchesMuscle 함수 (PostWorkoutLogModal.tsx L738 직전)

===== [5] 같은 머신을 운동 중 두 번 기록 가능한지 =====

■ 머신 선택 자료구조
  loggedIds: Set<string> (L3599):
    const [loggedIds, setLoggedIds] = useState<Set<string>>(new Set());

  Set이므로 같은 id는 한 번만 저장된다 (중복 자동 제거).

■ handleSaveExercise에서 loggedIds 추가 방식 (L3734-3735):
  setLoggedIds(prev => new Set([...prev, currentExerciseId]));
  Set에 spread하므로 이미 있는 id를 추가해도 중복 없이 하나만 유지된다.

■ 같은 머신 두 번 선택하려 할 때 막는 로직
  ExerciseSelectStep 내 각 머신 카드(L849, L904, L952):
    {loggedIds.has(m.id) && (
      <View style={s.cardCompletedOverlay}>
        <Text style={s.cardCompletedTxt}>완료</Text>
      </View>
    )}
  "완료" 오버레이가 표시되지만 disabled 처리는 없음.
  즉 탭은 가능하지만 handleSelectExercise (L3718-3721) 에서
    [id]: prev[id]?.length ? prev[id] : [{ weight: 60, reps: 10 }]
  이미 prev[id]에 기록이 있으므로 기존 세트 그대로 유지된다.

■ 로그 데이터 구조에서 중복 허용 여부
  logs: Record<string, SetEntry[]> (L3600) — 키가 machineId(string) 이므로
  같은 machineId 에 대한 기록은 항상 하나의 배열만 존재한다 (덮어쓰기 구조).

  selectedExercises (L3809-3822):
    const selectedExercises: ExerciseInfo[] = useMemo(() => {
      for (const id of loggedIds) { ... }   // Set 순회 → 유니크 항목만
    }, [loggedIds, gym]);

  WorkoutEntry(types.ts L83-92): machineId 컬럼에 유니크 제약은 없음.
  DB 구조상으로는 같은 세션에 동일 machineId의 entry를 여러 개 insert 가능하지만,
  현재 UI/로직이 이를 허용하지 않는다.

■ 결론
  현재 불가능.

  막히는 지점:
    1. loggedIds가 Set<string> 이므로 (L3599) 같은 id 중복 저장 자체가 안 됨.
    2. logs가 Record<string, SetEntry[]> (L3600) 이므로 같은 machineId 키는 하나만 유지됨.
    3. selectedExercises가 loggedIds(Set) 순회로 생성되므로 (L3812) 중복 항목 없음.

  가능하게 하려면 수정해야 할 곳:
    - loggedIds를 Set → Map<string, number>(몇 번 했는지 카운트) 또는 배열로 변경.
    - logs를 Record<string, SetEntry[]> → Record<entryKey, SetEntry[]> (entryKey = `${machineId}_${index}` 등) 로 변경.
    - handleSaveExercise에서 entry 저장 키를 machineId 단독이 아닌 복합키로 변경.
    - selectedExercises 빌드 로직도 중복 entry 허용 구조로 수정.

[분석]
  - 현재 동작: 같은 머신을 두 번 기록하는 것은 불가능하다.
  - 불가능한 핵심 이유: loggedIds(Set) + logs(Record by machineId) 이중 구조로 중복 제거됨.
  - 관련 코드 위치:
      loggedIds 선언: PostWorkoutLogModal.tsx L3599
      handleSaveExercise 중복 추가: PostWorkoutLogModal.tsx L3735
      logs 선언: PostWorkoutLogModal.tsx L3600
      handleSelectExercise 초기화: PostWorkoutLogModal.tsx L3718-3721
      selectedExercises 생성: PostWorkoutLogModal.tsx L3809-3822
