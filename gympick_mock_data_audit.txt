[배경]
GymPick 앱이 이미 프로덕션에 배포된 상태. 실제 Supabase 데이터 대신 하드코딩된 mock
데이터가 코드에 남아있으면, 실제 유저에게 엉뚱한 데이터가 보이거나 기능이 오작동할 수
있음. 전체 코드베이스에서 mock 데이터를 사용하는 곳을 빠짐없이 찾아서 정리한다.


[1] mock 데이터 파일 전체 파악

src 디렉터리에서 다음 패턴으로 mock 데이터 파일을 찾아줘:
- 파일명에 mock, dummy, fake, sample, test, fixture 포함
- data/ 폴더 안에 있는 파일들 (machines.ts 제외 — 이건 실제 머신 카탈로그 데이터)
- 파일 내용에 하드코딩된 배열/객체 형태의 더미 데이터가 있는 파일

각 파일에 대해:
- 파일 경로
- 어떤 데이터가 있는지 (예: 헬스장 목록, 유저 목록 등)
- 실제로 어느 화면/컴포넌트에서 import해서 쓰고 있는지
- Supabase로 대체됐는지 여부, 아니면 여전히 활성 사용 중인지


[2] 화면별 데이터 소스 점검

주요 화면들에서 데이터를 Supabase에서 가져오는지, mock에서 가져오는지 확인해줘:

- FindGymScreen: 헬스장 목록
- GymDetailModal: 헬스장 상세, 머신 목록
- HomeScreen: 오운완 피드, 이번 주 운동
- JournalScreen: 운동일지 목록
- AdminDashboard: 각 관리 항목들 (헬스장 승인 대기, 수정 요청, 신고 등)
- ManagerDashboard: 관리 헬스장 정보

각 화면별로 "Supabase 사용", "mock 사용", "혼용(Supabase 우선 + mock fallback)" 중 어느
상태인지 표로 정리해줘.


[3] 실제로 문제가 되는 mock 데이터 식별

[1][2] 결과를 바탕으로:
- 프로덕션에서 실제 유저에게 보이는 화면에 mock 데이터가 노출되는 경우
- mock 데이터가 Supabase 데이터를 덮어쓰거나 간섭하는 경우
- 완전히 제거해도 안전한 mock 파일

이 세 가지를 구분해서 알려줘.

코드는 수정하지 마. 점검 결과만 정리해줘.
