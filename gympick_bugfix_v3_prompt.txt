BUG FIX 1: Korean text input only accepts one character at a time
==================================================

ROOT CAUSE (confirmed):
In src/screens/manager/ManagerDashboard.tsx, inner view components such as
RegisterView, EditView, HomeView, etc. are defined INSIDE the component body:

  // WRONG - inside component body
  const RegisterView = () => { ... }

This means every time ManagerDashboard re-renders (e.g. on each keystroke),
React sees RegisterView as a brand new function reference,
unmounts the old subtree, mounts a fresh one,
and the Korean IME composition resets — losing the in-progress character.

FIX:
Move ALL inner view components (RegisterView, EditView, HomeView, MachinesView, etc.)
OUT of the ManagerDashboard component body and define them as SEPARATE components
at the MODULE LEVEL (outside the function).

They should receive state and handlers as props instead of closing over them.

Step 1: Identify all inner view components defined inside ManagerDashboard.
  Look for patterns like:
    const RegisterView = () => { ... }
    const EditView = () => { ... }
    const HomeView = () => { ... }
    const MachinesView = () => { ... }
  These are ALL defined inside the component function body.

Step 2: For each inner view component:
  - Cut the component definition out of the ManagerDashboard body
  - Paste it ABOVE the ManagerDashboard function (at module level)
  - Define a Props interface for each component
  - Pass all required state values and handlers as explicit props

Example transformation:

  BEFORE (wrong):
    export default function ManagerDashboard() {
      const [regForm, setRegForm] = useState(...)
      const setReg = (key) => (t) => setRegForm(f => ({ ...f, [key]: t }))

      const RegisterView = () => (
        <Field value={regForm.name} onChangeText={setReg('name')} />
      )
      return <RegisterView />
    }

  AFTER (correct):
    interface RegisterViewProps {
      regForm: GymForm
      onChangeField: (key: keyof GymForm) => (value: string) => void
      onNext: () => void
      onCancel: () => void
    }

    function RegisterView({ regForm, onChangeField, onNext, onCancel }: RegisterViewProps) {
      return (
        <Field value={regForm.name} onChangeText={onChangeField('name')} />
      )
    }

    export default function ManagerDashboard() {
      const [regForm, setRegForm] = useState(...)
      const handleChangeField = useCallback(
        (key: keyof GymForm) => (value: string) =>
          setRegForm(prev => ({ ...prev, [key]: value })),
        []
      )
      return <RegisterView regForm={regForm} onChangeField={handleChangeField} ... />
    }

Step 3: Use useCallback for ALL handler functions passed as props to prevent
  unnecessary re-renders:
    const handleChangeField = useCallback(...)
    const handleNext = useCallback(...)
    const handleSubmit = useCallback(...)

Step 4: Make sure every TextInput also has these props:
  autoCorrect={false}
  autoCapitalize="none"
  spellCheck={false}

Step 5: After refactoring, verify that typing Korean characters works correctly
  by tracing that no parent re-render causes child component remount.

BUG FIX 2: Machine selections lost when modal closes and reopens
==================================================

ROOT CAUSE (confirmed):
In ManagerDashboard.tsx:
  const [gymMachineIds, setGymMachineIds] = useState<string[]>([])

  const openMachines = (gym: ManagedGym) => {
    setGymMachineIds([...gym.machineIds])  // copies from gym object
  }

When machines are saved, only the component state (gyms) is updated.
The module-level MANAGED_GYMS array is never mutated.
When the modal closes and ManagerDashboard unmounts, all useState is discarded.
On next open, it reads from the original unchanged MANAGED_GYMS array.

FIX:
Step 1: Find MANAGED_GYMS (the module-level mock array in ManagerDashboard.tsx or a store file).

Step 2: Create a module-level store for managed gym data.
  If it doesn't exist, create src/data/managedGymStore.ts:

    export interface ManagedGym {
      id: string
      name: string
      location: string
      status: 'live' | 'pending' | 'rejected' | 'flagged'
      managerId: string
      machineIds: string[]
    }

    const managedGyms: ManagedGym[] = [
      {
        id: 'g01',
        name: 'IronHub Fitness',
        location: 'Downtown',
        status: 'live',
        managerId: 'u2',
        machineIds: [],
      },
      {
        id: 'g02',
        name: 'PowerZone',
        location: 'Midtown',
        status: 'live',
        managerId: 'u2',
        machineIds: [],
      },
    ]

    export function getManagedGymsByManager(managerId: string): ManagedGym[] {
      return managedGyms.filter(g => g.managerId === managerId)
    }

    export function updateGymMachines(gymId: string, machineIds: string[]): void {
      const gym = managedGyms.find(g => g.id === gymId)
      if (gym) gym.machineIds = [...machineIds]
    }

    export function getManagedGymById(gymId: string): ManagedGym | undefined {
      return managedGyms.find(g => g.id === gymId)
    }

Step 3: In ManagerDashboard.tsx, when opening the machine management view:
  Read machineIds from the store (not from component state):
    const gym = getManagedGymById(selectedGymId)
    setGymMachineIds(gym?.machineIds ?? [])

Step 4: When saving machine changes, write to the store:
  BEFORE closing or navigating back:
    updateGymMachines(selectedGym.id, gymMachineIds)

Step 5: Add a "저장" (Save) button to the machine management screen.
  When tapped:
    updateGymMachines(selectedGym.id, gymMachineIds)
    Show a brief success toast or Alert: "머신 목록이 저장되었습니다."

  Also add a prompt when navigating back without saving:
    If gymMachineIds has changed from the original, show Alert:
      "저장하지 않은 변경사항이 있습니다. 저장하시겠습니까?"
      Buttons: "저장", "저장 안 함"

Step 6: Add "보유 머신만 보기" filter to the machine management screen.

BUG FIX 3: Admin approve/reject buttons show no visual feedback
==================================================

ROOT CAUSE (confirmed):
In src/screens/admin/AdminDashboard.tsx:
  - pendingGyms (array state) and selectedGym (snapshot state) are separate, unconnected.
  - When approve/reject is tapped: pendingGyms updates correctly BUT selectedGym still holds
    the old object with status 'pending'.
  - The view is immediately popped (setViewStack(p => p.slice(0,-1))) before any re-render,
    so the status badge never appears.
  - GymDetailView is defined inside the component body (same issue as Bug 1),
    causing stale closure reads.

FIX:
Step 1: Move GymDetailView and ALL other inner view components OUT of the AdminDashboard
  component body to module level, same approach as Bug Fix 1.
  Pass pendingGyms, selectedGym, and all handlers as props.

Step 2: Fix the reviewGym handler to update BOTH pendingGyms AND selectedGym atomically:

  BEFORE (wrong):
    const reviewGym = (gym: PendingGym, action: ReviewStatus) => {
      Alert.alert(..., [{
        onPress: () => {
          setPendingGyms(prev => prev.map(g =>
            g.id === gym.id ? { ...g, status: action } : g
          ))
          setViewStack(p => p.slice(0, -1))  // pops immediately
        }
      }])
    }

  AFTER (correct):
    const reviewGym = useCallback((gymId: string, action: ReviewStatus) => {
      // Update both states atomically
      setPendingGyms(prev => {
        const updated = prev.map(g =>
          g.id === gymId ? { ...g, status: action } : g
        )
        // Also sync selectedGym from the updated array
        const updatedGym = updated.find(g => g.id === gymId)
        if (updatedGym) setSelectedGym(updatedGym)
        return updated
      })
      // Do NOT pop the view immediately — let user see the updated status badge first
    }, [])

Step 3: In the GymDetailView, after approve/reject show:
  - Status badge updates immediately (approved = green, rejected = red)
  - Replace the approve/reject buttons with a "목록으로 돌아가기" button
  - User taps this button to go back (setViewStack(p => p.slice(0, -1)))

  Example:
    {selectedGym.status === 'pending' ? (
      <View style={reviewButtons}>
        <TouchableOpacity
          style={approveBtn}
          onPress={() => reviewGym(selectedGym.id, 'approved')}

          <Text style={approveBtnText}>승인</Text>
        </TouchableOpacity>
        <TouchableOpacity
          style={rejectBtn}
          onPress={() => reviewGym(selectedGym.id, 'rejected')}
        >
          <Text style={rejectBtnText}>거절</Text>
        </TouchableOpacity>
      </View>
    ) : (
      <View>
        <View style={[statusBadge, selectedGym.status === 'approved' ? approvedStyle : rejectedStyle]}>
          <Text style={statusBadgeText}>
            {selectedGym.status === 'approved' ? '✓ 승인 완료' : '✗ 거절됨'}
          </Text>
        </View>
        <TouchableOpacity
          style={backBtn}
          onPress={() => setViewStack(p => p.slice(0, -1))}
        >
          <Text style={backBtnText}>목록으로 돌아가기</Text>
        </TouchableOpacity>
      </View>
    )}

Step 4: Fix the edit request approve/reject in the same way.
  Find the edit request detail view.
  Apply the same pattern: update state atomically, keep view open to show result,
  then let user manually go back.

Step 5: Also make sure the pending list correctly filters by status after updates:
