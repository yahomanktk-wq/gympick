# 목적 (읽기 전용 조사 — 코드/DB 수정 절대 금지)

Supabase `machines` 테이블의 `image_url` 컬럼이 어떤 행은 값이 채워져 있고 어떤 행은
비어있다(NULL 또는 빈 문자열). 그런데 값의 유무와 상관없이 앱에서는 머신 이미지가
정상적으로 출력되고 있다. 이 차이가 왜 발생하는지, 그리고 이미지가 어떤 경로로 실제
출력되고 있는지 파악하는 것이 목적이다. 아무것도 수정하지 말고 조사 결과만 보고해줘.

## 조사 항목

### 1. DB 데이터 확인 (Supabase)

- `machines` 테이블에서 `image_url`이 NULL이거나 빈 문자열인 행이 몇 개인지, 값이
  채워진 행이 몇 개인지 카운트 (가능하면 SQL 또는 supabase 클라이언트로 조회)
- `image_url`이 채워진 행 5개와 비어있는 행 5개를 샘플로 뽑아서 다음 컬럼들을 같이 보여줘:
  `id`, `brand`, `name`, `image_url` (컬럼명이 다를 수 있으니 실제 스키마 기준으로 조회)
- `image_url`이 채워진 값들의 실제 형태를 확인 (예: 전체 URL인지, 파일명만인지,
  Supabase Storage public URL 패턴인지, 외부 CDN URL인지)
- `image_url`이 채워진 행들이 특정 브랜드나 특정 시기에 등록된 머신에 몰려있는지
  (예: 최근 추가된 브랜드만 채워져 있다든지) 패턴이 있는지 확인

### 2. 코드에서 머신 이미지를 어떻게 렌더링하는지 확인

- `src/lib/machineImageUrl.ts` 파일 전체 내용을 확인해서:
  - `image_url` DB 컬럼 값을 실제로 사용하는지, 아니면 머신 `id`나 `brand`+`name` 조합으로
    별도의 URL/경로를 직접 만들어내는지 (예: Supabase Storage의 고정 버킷 경로 +
    `{machine.id}.png` 같은 패턴 조합)
  - `image_url`이 있을 때와 없을 때 로직이 분기하는지, 아니면 애초에 `image_url` 값을
    아예 참조하지 않는지
- `src/components/MachineCard.tsx`에서 이미지 소스(`source={{ uri: ... }}` 등)를 어떤
  값으로 채우는지 확인 — `machine.image_url`을 직접 쓰는지, 아니면 위 helper 함수를
  거치는지
- 머신 이미지가 Supabase Storage의 특정 버킷에 저장되어 있다면, 그 버킷 이름과 파일
  네이밍 규칙(`{brand}_{muscle}_{number}.png` 같은 패턴인지)도 확인해서 보고

### 3. 결론 정리

위 조사를 바탕으로 다음 질문에 답해줘:
- `image_url` 컬럼 값이 실제로 이미지 출력에 쓰이고 있는가, 아니면 사용되지 않는
  레거시/미사용 컬럼인가?
- 만약 사용되지 않는다면, 왜 일부 행에만 값이 채워져 있는지 짐작 가능한 이유가
  있는가 (예: 과거에 수동으로 채워 넣다가 중단됐다든지, 특정 기능에서만 참조한다든지)
- `image_url`을 참조하는 다른 코드(예: 관리자 화면, 브랜드 저작권 관리 등)가
  프로젝트 전체에 있는지 grep해서 확인 (`image_url` 문자열로 `src/` 전체 검색)
